# OfflineMusicLibrary 1.6.3 面向 NAS 与家庭影院的补强计划

审计日期：2026-08-09
对比对象：

- OfflineMusicLibrary 1.6.3 Windows x64
- 当前安装的网易云音乐 Windows 客户端 3.1.28.205001

## 实施状态（2026-08-09）

这份文档已作为正式产品路线使用。当前源码完成了 1.7.0 NAS Foundation 的第一轮实现：

- 已完成：根目录稳定 ID、类型、健康、延迟、最近在线和错误模型；v2 状态自动迁移到 v3，同时保留原 `LibraryFolders` 兼容字段。
- 已完成：短超时、可取消、不会阻塞界面的异步根目录/文件探测；设置页可查看并立即刷新全部目录状态。
- 已完成：完整队列、当前索引、位置、循环/随机模式、最近随机历史、等待根目录和输出设备的播放会话持久化。
- 已完成：NAS 离线与解码器故障分流；离线时不消耗解码器恢复次数，按 1、2、5、10、30 秒退避等待，恢复后从原位置继续。
- 已完成：本机持久封面/歌词缓存、容量上限和安全清理；NAS 离线时允许使用最后一份有效缓存。
- 已完成：NAS 5–30 秒缓冲，并向 LibVLC 同时传递 `file-caching`、`disc-caching` 和 `network-caching`。
- 已完成：专用临时目录回归，以及原有全部确定性检查；没有启动主播放器或改写真正曲库状态。

尚未完成或不能由静态测试代替：

- 真实 UNC 与映射盘的休眠/唤醒、Wi-Fi 抖动、凭据失效和长时间断线验收。
- 技术媒体信息的独立持久缓存与批量后台预热策略。
- 真实 DAC、HDMI 功放、WASAPI 独占、位完美、无缝播放、CUE 和多声道验收；这些仍属于 1.8.0。
- 10-foot 全屏、手柄/遥控器与 LAN 遥控；这些仍属于 1.9.0。

因此当前实现应视为 1.7.0 开发基线，不冒充已经通过真实 NAS、DAC 或 AVR 的稳定版。

## 1. 一句话结论

OfflineMusicLibrary 1.6.3 已经具备比网易云更可信的“本地曲库底座”：离线优先、网络盘失联时不清空曲库、增量扫描、三代状态恢复和播放引擎自愈都已经存在。

接下来不应该追网易云的账号、云盘、推荐、评论、会员或在线曲库，而应按下面的顺序补强：

1. 先把它做成 NAS 断线、休眠、重连时仍可靠的播放终端。
2. 再补真正面向功放、电视和 DAC 的高保真输出链路。
3. 最后补沙发距离可用的全屏界面、遥控器导航和纯局域网遥控。

核心判断：

> 1.6.3 的主要短板不是“内容不够多”，而是 NAS 会话语义、家庭影院音频输出和 10-foot 客厅交互还不完整。

## 2. 范围与明确排除项

本计划严格限定为本地存储、NAS 和家庭局域网使用。

### 允许

- 本机磁盘、移动硬盘、UNC 路径、SMB 共享和映射网络盘。
- 本机持久缓存封面、歌词、技术元数据和有限的播放缓冲。
- 局域网内手机或平板遥控，但不把音频转发到互联网。
- Windows 音频设备、USB DAC、HDMI 功放、电视和家庭影院接收机。
- 现有网易云歌单/历史导入作为一次性迁移工具。

### 不进入运行时路线

- 账号体系、会员、云盘、在线搜索、在线推荐和在线歌词。
- 评论、动态、社区、直播、播客分发和广告。
- 依赖公网 API 才能启动、浏览、搜索或播放。
- 自动上传媒体、远程遥测或强制联网授权。
- 把网易云导入功能变成 NAS 播放所必需的依赖。

原则是：即使路由器没有 WAN、网易云完全不可访问，曲库浏览、播放、队列、歌词、遥控和恢复仍应正常工作。

## 3. 审计方法与证据边界

本次没有启动或操控两个播放器界面，也没有进行真实扬声器、DAC、电视或功放播放。

检查内容包括：

- 1.6.3 发布目录、版本信息、README、发布说明、源码和测试项目。
- 网易云安装目录中的版本信息、原生播放器二进制字符串和界面资源包。
- 对 CUE、响度、WASAPI、全屏、设备恢复、NAS 缓存、队列持久化等关键词和实现入口进行静态核对。

文中使用三种结论：

- **已确认**：源码、模型、测试或安装文件中存在明确实现。
- **源码未见**：已对当前源码树进行针对性搜索，没有发现对应实现；不代表底层库绝对做不到。
- **需要实机验收**：必须连接真实 NAS、HDMI 功放、DAC、电视或遥控器后才能确认。

网易云二进制中存在的能力不一定全部在当前界面公开，因此本计划只把它们作为设计参考，不把静态字符串等同于已完成的用户验收。

## 5. 1.6.3 必须保留的优势

下面这些不应该在重构 NAS/家庭影院功能时被破坏：

1. **不可达曲库保护**
   - MusicLibraryService.ScanAsync 会区分可用根目录与受保护的不可用位置。
   - 网络盘、移动盘或光驱不可达时，既有索引不会被当作“文件已删除”。

2. **网络盘温和扫描**
   - ResolveScanParallelism 对网络盘、移动盘和光驱使用单路读取，避免随机 I/O 抖动。

3. **状态文件安全**
   - library-v2.json、backup 和 previous 三代恢复。
   - 临时落盘、写锁和原子替换不能为了新功能而弱化。

4. **播放恢复**
   - PlaybackService.RecoverAsync 会重建 LibVLC，并从原位置继续。
   - 安全模式会切到 DirectSound、软件解码、更高缓存，并关闭高风险音效。

5. **现有本地交互**
   - 播放队列、播放下一首、迷你播放器、桌面歌词、任务栏控制、全局快捷键和媒体键。
   - 标准、黑胶、歌词等播放页不需要推倒重做。

6. **不改写媒体文件**
   - 新的响度、技术元数据、封面缓存和 CUE 索引应优先写入本地数据库或旁车缓存，不应批量重写 NAS 中的健康媒体。

## 6. 从网易云只借鉴这些本地能力

| 网易云中可确认的成熟点 | OfflineMusicLibrary 的对应实现方向 |
|---|---|
| CUE 文件、整轨音频和 offset 虚拟分轨 | 增加 CUE 解析器、虚拟 TrackModel、按文件路径加偏移构造稳定 ID |
| loudnessBalance 与 volumeDelta | 增加 ReplayGain Track、ReplayGain Album、R128 三种本地响度模式 |
| WASAPI Exclusive 原生渲染代码 | 增加“共享兼容 / WASAPI 独占 / 位完美”明确输出档案 |
| 全屏纯享 | 增加真正的全屏 10-foot 播放页，而不是只隐藏侧栏 |
| SQ、Hi-Res 等简洁标签 | 使用“FLAC · 24-bit · 96 kHz · 2.0”等事实标签 |
| 系统恢复和音频端点更新线索 | 对功放开关机、HDMI 重连、USB DAC 热插拔做显式恢复 |
| 完整模式、mini 模式、托盘、桌面歌词联动 | 在现有功能上统一状态与焦点，不重复造一套播放器 |

不应借鉴：

- 会员音质分级和能力锁定。
- 在线音效商店、账号绑定和云端配置。
- 在线内容优先的信息架构。
- 任何必须登录、联网或上传媒体信息才能工作的流程。

## 7. P0：先完成 NAS 可靠性

### P0.1 为每个曲库根目录建立健康状态

当前 LibraryFolders 只是字符串列表。建议升级为稳定 ID 对应的根目录配置与运行状态：

- 路径类型：本机、移动盘、UNC、映射盘。
- 状态：在线、延迟过高、离线、正在重连、需要系统凭据。
- 最近成功访问时间、最近扫描时间、探测延迟和最近错误。
- 独立的扫描、重试、缓存和离线浏览策略。

约束：

- 不在应用状态文件中保存 NAS 密码。
- 优先使用 Windows 已建立的 SMB 会话和凭据管理。
- 根目录探测必须异步、可取消、有短超时，不能阻塞主窗口。
- 根目录离线只改变健康状态，不删除曲目、歌单、收藏或播放历史。

### P0.2 增加持久封面、歌词和技术元数据缓存

当前问题：

- CoverService 的曲目缩略图缓存仅存在于进程内。
- 应用重启且 NAS 仍离线时，嵌入封面和旁车封面无法重新读取。
- LyricsService 每次仍从媒体旁的 LRC 文件读取。
- TrackModel 只持久保存基础格式和时长，没有完整技术信息。

建议：

- 在本机数据目录增加 artwork-cache、lyrics-cache 和 media-probe-cache。
- 以曲目稳定 ID、文件长度和修改时间戳作为缓存版本依据。
- 缓存尺寸受控，可在设置中查看、清理和重建。
- NAS 离线时仍可浏览专辑封面、已缓存歌词和技术标签。
- NAS 恢复后只刷新发生变化的资源。

这项应列为 P0，因为“索引没丢，但封面、歌词全空白”不算完整的离线浏览。

### P0.3 把 NAS 故障与解码器故障分开处理

现有看门狗是通用引擎恢复，适合处理 LibVLC 卡死，但 NAS 断线需要不同状态机。

建议播放状态：

- Playing
- Buffering
- WaitingForRoot
- Reconnecting
- RecoveringDecoder
- Skipped
- Stopped

处理原则：

1. 先快速判断文件或所属根目录是否可访问。
2. 根目录离线时不要反复重建解码器，应进入 WaitingForRoot。
3. 使用有上限的退避探测，例如 1、2、5、10 秒后进入低频等待。
4. NAS 回来后再重建播放引擎，并从原时间点恢复。
5. 用户始终可以选择继续等待、跳过当前曲目或停止。
6. 无论当前曲目是否恢复，后续队列不能丢失。

### P0.4 增加 NAS 专用缓冲与下一首预取

当前 500–5000 ms 的 file/disc caching 更像本机稳定性配置，不足以覆盖 NAS 休眠、Wi-Fi 抖动和高码率多声道文件。

建议：

- 本机文件继续使用低延迟缓存。
- UNC/SMB 文件提供 5–30 秒可配置读前缓冲。
- 可选使用本机临时环形缓存，设置明确的容量上限。
- 在当前曲目接近结束时预取下一首的文件头、元数据和首段音频。
- 不默认整首复制，不在用户不知情时占满系统盘。
- 缓冲和预取失败只能影响当前媒体，不能卡住整个 UI。

### P0.5 持久化完整播放会话

当前 AppState 保存 LastTrackId 和 LastPlaybackPositionMs，但不保存完整队列。

建议保存：

- 队列中的稳定曲目 ID。
- 当前索引与播放位置。
- 重复、随机及最近随机历史。
- 暂时离线曲目的占位状态。
- 当前选定输出档案和根目录等待状态。

恢复规则：

- 应用崩溃、HTPC 重启或 NAS 暂时离线后，队列仍应原样存在。
- 曲目暂时不可达时显示“等待 NAS”，而不是从队列中删除。
- 用户明确清空队列时才永久删除会话。

### P0.6 NAS 阶段验收标准

| 场景 | 通过标准 |
|---|---|
| NAS 在启动前离线 | 主界面可进入；曲目、歌单、收藏、封面缓存仍可浏览；不清空任何索引 |
| 播放中拔网线 | 界面不假死；显示 WaitingForRoot；队列和位置保持 |
| 两分钟内恢复网络 | 自动重新打开当前文件，并在原位置附近继续 |
| NAS 长时间休眠 | 探测进入低频退避，不持续高频访问或刷日志 |
| 映射盘盘符变化 | 能通过根目录修复向导重定向，不把全部曲目视为新文件 |
| 应用重启且 NAS 仍离线 | 上次队列、当前项、位置和缓存封面仍存在 |
| 扫描期间断线 | 扫描可取消；已存在数据不丢；每个根目录有独立结果 |

## 8. P1：补齐高保真和家庭影院输出

### P1.1 明确区分三种输出档案

建议至少提供：

1. **共享兼容**
   - 默认模式。
   - 允许系统混音、应用音量、EQ、空间效果和响度处理。

2. **WASAPI 独占**
   - 独占目标设备。
   - 可按曲目切换采样率和位深。
   - 明确显示当前设备、格式和独占状态。

3. **位完美**
   - 在 WASAPI 独占基础上启用严格旁路。
   - 自动关闭应用音量、播放速度、EQ、空间效果、crossfade、响度增益和其他 DSP。
   - 如果源格式或设备不支持，必须提示实际回退到的格式，不能仍显示“位完美”。

现有“WASAPI”选项只能说明选择了 mmdevice 输出模块，不能自动等同于独占或 bit-perfect。

### P1.2 设备热插拔和 HDMI 功放恢复

家庭影院的常见故障不是文件损坏，而是：

- 功放比 HTPC 晚开机。
- 电视切换输入导致 HDMI 音频端点消失。
- Windows 从睡眠恢复后设备 ID 或默认设备变化。
- USB DAC 被拔出后重新插入。

建议：

- 订阅 Windows 音频端点添加、移除、默认设备变化和状态变化。
- 提供“等待原设备”“回退到系统默认”“停止播放”三种策略。
- 原设备回来后可自动切回，但切回前应有用户配置。
- 设备恢复后重新确认采样率、声道布局、音量和独占状态。
- 在播放器中显示实际输出链路，而不只显示保存的设备名称。

### P1.3 ReplayGain 与 R128 响度

网易云的 loudnessBalance 说明成熟客户端会处理曲目间音量差。OfflineMusicLibrary 应使用开放、本地、可验证的标准：

- Off
- ReplayGain Track
- ReplayGain Album
- R128 / EBU R128

实现要求：

- 优先读取现有标签。
- 缺少标签时可选本机后台分析，结果写入本地数据库，不强制修改媒体。
- 提供削波预防和可选 true-peak limiter。
- 专辑模式必须保持专辑内部动态关系。
- 位完美模式下自动关闭响度处理，并清楚提示原因。

### P1.4 先做无缝播放，再做淡入淡出

优先级：

1. Gapless：现场专辑、古典连续乐章、DJ Mix 和 CUE 整轨的基本要求。
2. Crossfade：适合派对或随机播放，应为可选功能。

要求：

- 预加载下一首并避免先收到 EndReached 再临时创建播放器。
- 连续专辑默认 gapless，不默认 crossfade。
- crossfade 可设置 0–12 秒，并可按专辑边界关闭。
- 位完美模式默认禁用 crossfade。
- 使用可测量的 PCM 连续性测试，不仅以“听起来差不多”验收。

### P1.5 CUE、DiscNumber 与套装专辑

这是当前网易云本地播放相对明确、也最值得借鉴的能力之一。

建议模型：

- 一个媒体文件可生成多个虚拟曲目。
- 稳定 ID 由规范化媒体路径、CUE 路径和起始 offset 共同生成。
- 保存 TrackNumber、DiscNumber、Index、Pregap、Start、Duration。
- CUE 移动或 NAS 根目录重定向后，尽可能保留收藏、播放次数和歌单引用。
- 专辑排序改为 DiscNumber → TrackNumber → Title。
- 支持多碟、Box Set 和“整轨/分轨”标识。

### P1.6 HDMI 多声道、声道映射与可选直通

当前播放器能读取声道数，但家庭影院还需要明确输出策略：

- 2.0、2.1、5.1、7.1 PCM 的实际声道布局。
- 不默认把双声道强制上混。
- 可配置中心、低音炮和后环绕映射策略。
- 显示源声道布局与实际输出声道布局。
- 对音乐视频或演唱会素材，可选增加 AC3/DTS 直通。
- 直通时禁用应用音量、EQ、响度和空间效果，并明确由功放接管解码。

直通应在 PCM 多声道稳定后再做，避免同时扩大故障面。

### P1.7 技术元数据和事实标签

当前正在播放页已有 AudioCodec、SampleRate、Channels 和 AudioBitrate，但应补充并索引：

- 容器与编解码器。
- 位深。
- 采样率。
- 码率。
- 声道布局。
- 是否无损。
- CUE 虚拟轨信息。
- 实际输出设备、共享/独占状态和实际输出格式。

标签建议使用事实表达：

> FLAC · 24-bit · 96 kHz · 5.1 · WASAPI Exclusive

不使用需要会员解释的“臻音”“母带”等营销等级。

### P1.8 音频阶段验收标准

| 场景 | 通过标准 |
|---|---|
| 44.1/48/96/192 kHz 曲目切换 | 功放或 DAC 显示与源文件一致；应用显示实际而非期望格式 |
| 16-bit 与 24-bit 文件 | 位深可识别；位完美状态只在真实匹配时亮起 |
| HDMI 功放播放中关机再开机 | 应用不崩溃；按策略等待、回退或恢复 |
| USB DAC 拔插 | 设备状态及时更新；队列和播放位置不丢 |
| 现场专辑连续曲目 | 切歌无可感知空白、重复或截断 |
| CUE 整轨 | 每个虚拟曲目可选、可 seek、可加入歌单并正确恢复 |
| ReplayGain Album | 专辑内部动态关系保持，跨专辑总体响度更一致 |
| 5.1 PCM | 功放识别 5.1，声道测试文件映射正确 |

## 9. P2：真正的家庭影院交互

### P2.1 全屏 10-foot 模式

现有沉浸页是良好基础，但当前主窗口最小尺寸、控件密度和鼠标模型仍是桌面应用。

建议新增独立“家庭影院模式”：

- 真正全屏，适配 1920×1080 和 4K。
- 3 米距离可读的标题、时间、状态和焦点环。
- 16:9 安全边距，避免电视过扫描裁切。
- 主层只保留封面/背景、曲名、艺术家、进度、播放控制和队列入口。
- 技术信息和歌词作为可切换层，不长期挤占画面。
- 长时间无操作后自动隐藏控制层，但保留必要状态。
- Escape、Back 或遥控器返回键行为一致。

### P2.2 手柄、遥控器和方向焦点

现有快捷键适合键盘，但家庭影院需要完整焦点导航：

- 方向键/D-pad：移动焦点。
- A/Enter：确认。
- B/Escape/Back：返回。
- 播放、暂停、上一首、下一首和音量媒体键。
- XInput 手柄为第一阶段。
- 红外遥控映射键作为兼容层。
- HDMI-CEC 受硬件和驱动限制，可放到后续实验阶段。

验收要求是从启动到选择专辑、播放、查看队列和退出全屏全程不使用鼠标。

### P2.3 纯局域网手机遥控

可以增加 LAN-only 遥控，但必须与“在线服务”彻底区分。

安全边界：

- 默认关闭。
- 只绑定用户选择的私有网络适配器。
- 首次配对使用一次性 PIN 或短期二维码令牌。
- 每台设备可撤销授权。
- 不开放 NAS 任意文件浏览，只能查询已索引曲库。
- 不把音频转发到手机，不连接外部服务器。
- 路由器 WAN 断开时仍可完整工作。

第一版功能：

- 播放、暂停、上一首、下一首、seek 和音量。
- 搜索本地曲库。
- 查看、添加、排序和清空队列。
- 选择播放模式和输出档案。
- 查看 NAS 根目录状态。

### P2.4 HTPC 生命周期

当前已有开机启动、启动最小化、启动自动播放、记忆进度和定时关闭，可继续补：

- 系统挂起前保存播放会话并暂停。
- 系统恢复后先等待 NAS 与音频端点，再按策略恢复。
- 播放视频或全屏音乐时可选阻止屏保。
- 显示器关闭或输入切换时可选继续音频、暂停或停止。
- 定时功能增加“播完当前曲目”“播完当前专辑”“仅停止播放”，不只退出程序。
- AVR 尚未出现时显示明确等待界面，而不是静默回退。

## 10. P3：曲库与诊断精修

这些有价值，但不应抢占 P0/P1：

- 根据技术元数据筛选 24-bit、96 kHz、多声道、CUE 和视频。
- 多碟专辑、Box Set、Booklet 和扫描图入口。
- 通过文件指纹辅助识别 NAS 重命名、移动和根目录迁移。
- 缓存占用、最近失败根目录、最后一次成功扫描和设备恢复次数面板。
- 输出档案：纯音频、家庭影院、夜间、兼容模式。
- 可导出/导入本地配置、队列和曲库索引备份。
- 对本地推荐页面改名或说明为“本地发现”，明确不访问互联网。

暂不建议优先实现：

- 多房间同步播放。
- 自建转码服务器。
- DLNA/UPnP 全套服务端和渲染器。
- 在线元数据刮削。

这些都可能演变成另一个大型项目，应在 NAS 播放和单房间家庭影院稳定后单独评估。

## 13. 实机测试矩阵

### NAS

- UNC 路径与映射盘各一套。
- 有线千兆、Wi-Fi、短时断线、长时断线。
- NAS 休眠、唤醒、共享重启和权限失效。
- 1 万首以上曲库的首次扫描与增量扫描。
- 应用启动时 NAS 离线、运行中离线、扫描中离线。

### 音频

- DirectSound 共享。
- WASAPI 共享。
- WASAPI 独占。
- HDMI 功放。
- USB DAC。
- 蓝牙设备仅作为兼容回退测试，不作为位完美基准。

### 媒体

- FLAC 16/44.1、24/96、24/192。
- MP3、AAC、APE、OPUS、NCM。
- 单文件 CUE、跨文件 CUE、多碟专辑。
- 连续现场专辑和古典无缝曲目。
- 5.1 FLAC/WAV。
- 含 AC3/DTS 音轨的本地视频。

### 生命周期

- 应用崩溃后恢复。

### 客厅交互

- 未配对设备无法调用控制接口。

## 14. 完成定义

任何 NAS/家庭影院版本都至少要满足：

1. 无互联网时完整可用。
2. 根目录离线不会清空曲库或歌单。
3. 网络文件访问不在 UI 线程同步执行。
4. 播放失败不会丢失队列和当前会话。
5. 缓存有容量上限、可清理、可重建。
6. 不批量改写健康媒体文件。
7. “位完美”“独占”“5.1”等状态必须显示实际结果，而不是配置愿望。
8. 自动化测试、静态构建和真实 NAS/功放验收分开记录。
9. 网易云导入保持可选迁移工具，不进入播放核心依赖。

- 为会员、评论、在线推荐和云盘重构核心。
- 让任何在线接口成为本地播放的单点故障。
