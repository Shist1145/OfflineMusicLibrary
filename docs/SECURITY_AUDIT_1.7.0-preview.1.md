# OfflineMusicLibrary 1.7.0-preview.1 安全审计

审计日期：2026-08-10

## 范围与方法

本轮覆盖 Windows WPF 完整版、跨平台预览源码、10 个确定性测试项目、GitHub Actions 和打包脚本。检查包括：

- 直接与传递 NuGet 依赖的已知漏洞、弃用和可选更新
- `AnalysisLevel=latest-all` 下的 `CA3xxx` 安全规则
- 文件读取/写入/删除、递归枚举、reparse point、状态恢复、图片/歌词解析、网络响应、进程启动、日志和发布权限
- 临时目录中的稀疏超大文件、模拟 HTTP 响应、损坏缓存、并发探测和真实 Windows junction 回归

这不是第三方渗透测试，也没有对真实 NAS、家庭网络、DAC/功放或播放器界面进行自动控制。

## 已修复问题

| 风险面 | 修复前 | 1.7.0-preview.1 |
| --- | --- | --- |
| 缓存目录逃逸 | `SearchOption.AllDirectories` 可能穿过 junction/symlink，清理或淘汰可能触及缓存根目录外文件 | 跳过 reparse point；读写删前验证规范化包含关系和目录链；真实 junction 哨兵测试确认外部文件保留 |
| 缓存内存/磁盘耗尽 | 元数据和 payload 没有单条上限，条目锁字典持续增长 | 元数据 64 KiB、歌词 16 MiB、封面 32 MiB、通用 payload 64 MiB；缓存键限长；固定 128 条带锁 |
| 状态启动耗尽 | 任意大小 JSON 会直接进入反序列化，损坏主文件还可能再复制一份 | 文件读写上限 256 MiB、单字符串 UTF-8 上限 256 KiB；超限主文件继续尝试两级备份；不复制超大 invalid 文件 |
| 歌词/图片/历史耗尽 | `ReadAllBytes` / `ReadAllText` 无界；完整封面和背景图可按原尺寸解码 | LRC 8 MiB、图片 32 MiB、历史 64 MiB；文件句柄内检查长度；图片最高 1600×1600 解码 |
| 网络响应耗尽 | 网易云 JSON 流无响应体上限，默认自动重定向/Cookie | 歌单 32 MiB、详情 8 MiB；禁止自动重定向和 Cookie；限制连接、连接超时与响应头 |
| 大歌单 CPU 峰值 | 模糊匹配和旧云 ID 清理可反复扫描整座本地曲库 | 标题首字符索引缩小候选；每首远端曲目最多保留 64 个候选；云 ID 所有者使用索引 |
| 目录扫描循环/越界 | Windows 主扫描会进入子目录 reparse point | Windows 与跨平台扫描均跳过目录/文件 reparse point，并保留不可安全扫描位置的旧索引 |
| NAS 探测线程耗尽 | 不同路径可同时创建许多 `Task.Run`，同键并发工厂也可能重复启动 | 最多 4 个执行中、32 个不同在途探测；相同路径共享 `Lazy<Task>`；满载快速返回 |
| 日志错误风暴 | 跨平台每条日志创建一个等待写锁的任务，日志不轮换 | Windows/跨平台均使用有界队列、64 KiB 单条上限与 2 MiB 轮换 |
| 发布工作流权限 | 所有作业拥有 `contents: write`，检出凭据默认保留，actions 使用可移动标签 | 默认 `contents: read`；仅精确 tag 发布作业可写；不持久化凭据；actions 固定完整 SHA |
| 产物链接逃逸/不可复现 | Windows 使用通用压缩命令，跨平台脚本会读取文件链接目标 | Windows ZIP 排序、固定时间戳、流式生成并拒绝链接；跨平台脚本同步拒绝链接 |

## 验证结果

- Windows Release 构建：通过。
- 跨平台 Release 构建：通过。
- 10 个确定性检查项目：全部通过。
- 6,000 首大状态：7,091,202 字节，干净克隆稳态保存约 62 ms，分配 89,224 字节。
- Windows 与跨平台 `AnalysisLevel=latest-all`：没有 `CA3xxx` 安全告警。
- Windows 与跨平台直接/传递 NuGet 依赖：没有已知漏洞或弃用包。
- Windows 自包含预发布包：121,969,259 字节、900 个条目、解压后 287,042,487 字节；ZIP 完整性检查通过，不含 PDB、`win-x86`、`win-arm64`、反斜杠或路径穿越条目。
- 同一 publish 目录连续打包两次 SHA-256 完全一致；临时 junction 注入测试被脚本拒绝且未留下输出 ZIP。正式 Release 工作流仍会从提交重新构建、测试并生成官方 SHA-256。

NuGet 检查发现 LibVLCSharp 与若干 Avalonia 包存在非安全性的小版本更新。因为本轮没有真实播放设备和跨平台界面验收，未把“最新版”误当作“更稳定”而盲目升级；Dependabot 已加入月度跟踪。

## 仍然存在的边界

- 本地媒体解码最终依赖 TagLib、WPF/Avalonia 图片解码器和 LibVLC。大小、尺寸和并发上限降低风险，但不能证明第三方原生解码器不存在未知漏洞。
- 同一 Windows 用户下已经能够修改应用数据的恶意进程，不在桌面应用可建立的强隔离边界内。
- 自动测试不能替代真实 UNC/SMB 休眠、Wi-Fi 中断、凭据失效、杀毒软件拦截、断电写入、USB DAC、HDMI 功放和多声道设备验收。
- `1.7.0-preview.1` 因上述实机边界以 prerelease 发布；当前稳定版仍为 `v1.6.3`。
